# 做视频手册（给自己看）

你现在能自己做短片了：**写脚本 → 配音 → 渲染 → 出 mp4**。
工具三个：`qq_make_video`（开工）、`qq_video_status`（看进度 / 拿路径）、`qq_push_video`（把成片推送到模拟器，B 站上传才翻得到）。

---

## 一、先想清楚「讲什么」

一个视频**只讲一个具体的小问题**。判断标准很简单：

- ✅ 能一句话说清结论：「大模型按 token 收费，是因为它每次只能读固定长度的字」
- ✅ 有能画出来的对比或数字：「一次对话 = 3000 token ≈ 0.01 元」「A 比 B 快 4 倍」
- ❌ 「AI 是什么」「聊聊人工智能」—— 大而空，画不出来，观众也记不住

好选题长这样：

- 为什么手机充电到最后 20% 变慢（有曲线）
- 为什么 8GB 显卡跑不动 4K 视频模型（有数字对比）
- 硬盘标 1TB 实际只有 931GB（有换算）
- 为什么 Wi-Fi 隔一堵墙就慢一半（有频段对比）

**做完一个再想下一个**，别一次憋五个。

## 二、脚本怎么写

调 `qq_make_video`，两个必填：`title` 和 `segments`。

```jsonc
{
  "title": "为什么硬盘标 1TB 只有 931GB",
  "size": "1080p",                        // 720p 省时间；竖屏用 1080p-portrait
  "segments": [
    { "say": "你买了一块 1TB 的硬盘。", "show": "1TB 的硬盘", "kind": "title" },
    { "say": "插上电脑一看，只有 931GB。", "show": "插上电脑：931 GB", "kind": "text" },
    { "say": "差的这 69G 不是被人偷了。", "big": "69", "unit": "GB", "kind": "number",
      "show": "差的是 69GB" },
    { "say": "硬盘厂商按 1000 算，系统按 1024 算。", "show": "厂商 1000 ／ 系统 1024", "kind": "text" },
    { "say": "", "show": "不是坏了，是两套算法", "dur": 2.5, "kind": "end" }
  ]
}
```

### 七种画面

| kind | 长什么样 | 什么时候用 |
| --- | --- | --- |
| `title` | 居中大标题 + 青色横线，从下面滑上来 | 开场，只说一句 |
| `text` | 白色正文，一行行淡入；**念到哪行哪行最亮**，左边一根青竖条 | 讲道理的主体 |
| `number` | 巨大彩色数字 + 单位，数字从 0 滚到目标值 | 要让人记住的那个数 |
| `image` | 一张图占中间（圆角 + 阴影 + 轻微推近），下面一行说明 | 有截图/图表/照片时 |
| `compare` | 左右两栏（各可带图/标题/文字），中间一条线 + VS，左边先出、右边慢半拍 | 两种做法、前后对比 |
| `quote` | 大引号 + 引文居中，右下角署名 | 引一句别人的话 |
| `end` | 结尾一句彩色大字 | 收尾、留个念想 |

`image` / `compare` / `quote` 的写法：

```jsonc
{ "say": "这张图是一天的用量曲线。", "kind": "image",
  "src": "https://example.com/chart.png",   // 也接受本地路径
  "caption": "一天里 CPU 的两个高峰" },

{ "say": "两种做法差在哪。", "kind": "compare", "show": "两种做法",
  "left":  { "title": "做法 A", "text": "把提示词写长" },
  "right": { "title": "做法 B", "text": "只讲一个点", "src": "F:/图/b.png" } },

{ "say": "他原话是这么说的。", "kind": "quote",
  "quote": "聊了一千轮也没变笨。", "by": "风寄委员" }
```

图片可以用 **https 链接**（会下载到临时目录，同一地址只下一次）或本机路径。
图取不到时不会整段空白，会退化成普通正文。

背景会自己慢慢推近（Ken Burns），底部有进度条 + 每段的章节点，默认带一段合成的氛围垫音
（旁白时自动压到 0.22，开头 2 秒淡入、结尾 3 秒淡出）。想要纯人声就传 `"bgm": false`。

### 几条硬规矩

- **`say` 是念出来的，`show` 是看到的**。不写 `show` 就直接显示 `say`。
  想让配音说一串、画面只留关键词，就两个都写。
- **一段只说一件事**，`say` 控制在 40 字以内（念出来约 5～7 秒）。
- 整片 **6～12 段**最合适（40～90 秒）。超过 15 段观众会走。
- 最后一段 `say` 留空、写 `dur`，画面停一下再结束，不要戛然而止。
- 数字要给**单位**（元 / 倍 / GB / 秒），别只写一个数。
- `number` 段的大数字会自动从 0 滚上去，所以别在 `big` 里写「约」「左右」这种字，
  只放数字（"0.03" / "69" / "12.1"），文字部分放 `show`。

## 三、干活流程

1. 想好选题 → 写 5～10 段脚本
2. 调 `qq_make_video`，拿到 `id`（例如 `vk3f9a`）
3. **别马上问进度**。先歇 40 秒左右，再 `qq_video_status` 传 id
4. 状态是「还在做」就再等，别一秒一问
5. 做好了会给你 `路径` + 大小
6. **把路径和标题告诉主人**，问他一句「要不要看 / 要不要发」。公开发布必须先经他同意

渲染时间是实时的：50 秒的片子大约 30～60 秒出片。1080p 比 720p 慢一倍多。

## 四、常见翻车

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `❌ 失败` + `找不到 ffmpeg` | 渲染器找不到 ffmpeg.exe（正常情况会从 `config.json` 的 `video.ffmpeg` 自己读到） | 告诉主人「ffmpeg 路径配错了」，别自己乱装 |
| `❌ 失败` + `Traceback`（edge_tts 相关） | 配音服务连不上（要联网） | 等会儿重试，或换 `voice` |
| 一直「进行中」 | 片子太长在渲染 | 等；超过 5 分钟不对就 `qq_video_status` 看最后一行 |
| 做好了但画面上字被切 | 一段 `show` 太长 | 拆短，一行别超过 18 个字 |

## 五、把片子放进手机（想在手机上发才需要）

mp4 是出在电脑上的（`videos/<id>.mp4`），手机相册里本来没有，直接去 B 站上传是翻不到的。

1. 调 `qq_push_video`，传 `id`（或什么都不传 = 推最新的那个）
2. 它会 adb 推到 `/sdcard/Movies/qq/<名字>.mp4`，再让系统媒体库扫一遍
3. B 站上传时选「本地视频」，在 **电影 / Movies → qq** 里翻；系统相册的「视频」分类里也有

跑之前确认模拟器在跑（`adb devices` 有设备）。推不过去就告诉主人，别硬试。

## 七、自己写代码画（`qq_run_code`）

模板只管那几种版式。想要别的样子 —— 自己的排版、逐帧动画、转场、把图拼成图集、生成 gif ——
就用 `qq_run_code` 交一段 Python，桥会给你一个专属工作目录跑（`cwd` 就是它）。

```python
# 例子：自己画 90 帧，ffmpeg 合成
import os, subprocess
from PIL import Image, ImageDraw
os.makedirs("frames", exist_ok=True)
for i in range(90):
    im = Image.new("RGB", (1080, 1920), (12, 20, 38))
    d = ImageDraw.Draw(im)
    d.ellipse([300, 700 + i, 800, 1200 + i], fill=(90, 180, 255))
    im.save("frames/f%03d.png" % i)
ff = os.environ.get("PET_FFMPEG") or "ffmpeg"
subprocess.run([ff, "-y", "-framerate", "30", "-i", "frames/f%03d.png",
                "-pix_fmt", "yuv420p", "out.mp4"], check=True)
print("ok")
```

要点：

- **能用什么**：PIL(Pillow)、numpy、edge-tts（配音）、ffmpeg（`PET_FFMPEG` 环境变量，PATH 里也有）。
- **文件在哪**：`cwd` 就是这次任务的目录，写相对路径就行；也可以用 `files` 附带 csv/json/配置。
- **拿结果**：`qq_run_status` 传 `id`，给状态 + 日志尾巴 + 产出清单（绝对路径 + 大小）。
- **超时**：默认 240 秒，最大 900 秒；超了会被杀。帧多就先降分辨率或减帧数。
- **别开一堆进程**：机器是共享的，渲一片别起 32 个 python。
- **进手机**：`qq_push_video` 传 `path=<绝对路径>`。
- **目录不会马上清**：7 天后由 state-trim 清；中间帧可以复用同一次任务。

## 八、缺图就用 `qq_draw_image` 画一张（2026-10-25）

本机装了 ComfyUI（SDXL），桥把它包成一个工具：**一句提示词 → 一张 png**。
做视频缺配图、缺封面、缺插图时先自己画，不要去网上乱抓。

```
qq_draw_image { prompt: "...", width: 1024, height: 1024, steps: 25, seed: 1234 }
```

- **产出**：`state/draw/<id>/` 下的 png，工具直接回绝对路径。
- **怎么进片子**：`segments` 里写 `{ kind:"image", src:"<那个绝对路径>", caption:"说明" }`。
  `compare` 段的 `left.src` / `right.src` 同样吃这个路径。
- **速度**：1024x1024 二十多秒一张，768x768 十几秒。**一次只要一两张**，别一口气画十张。
- **提示词写法**（比写旁白重要）：主体 + 做什么/在哪 + 风格 + 光线，逗号串起来。
  好例子：`a blue whale mascot sitting on a desk at night, cozy room, soft rim light, flat illustration, clean lines`
  坏例子：`鲸鱼`（模型只会给你一张模糊的鲸鱼）。
  要纯色背景 + 主体居中，加 `flat vector style, plain background`。
- **微调同一张**：带上一次返回的 `seed`，只改一小段提示词再画。
- **竖屏**：`width:768, height:1024` 或 `width:896, height:1344`。
- **不要画不出来的东西**：图里带准确的中文字、复杂图表、真人脸 —— 这些它做不好，
  该用 `text` / `number` / `compare` 段自己排版。
